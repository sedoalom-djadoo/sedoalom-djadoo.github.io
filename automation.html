From manual exports to a nightly QuickBooks API feed

Automation · In production since summer 2026 · Refreshed every 24 hours

The first version of the financial dashboard ran on Excel files exported by hand from QuickBooks. It worked, but it depended on someone remembering to export, and on the export settings being the same every time. When either slipped, the dashboard went quietly out of date.

I replaced the ledger export with a script that calls the QuickBooks Online API every night and writes a clean file that Power BI picks up on its scheduled refresh.

Why the Reports API

QuickBooks Online has two families of endpoints. The entity API returns invoices, bills and journal entries one by one; turning those into a general ledger means rebuilding accounting logic that QuickBooks already applies. The Reports API returns the general ledger as QuickBooks itself computes it.

The native Power BI connector and the paid third-party connectors I looked at all sit on the entity API. Calling the Reports API directly gave the same numbers as the manual export, with no gateway and no extra licence.

How I rolled it out

  1. I registered an Intuit developer app and tested the authorization on the sandbox company first. The redirect URI has to match character for character, and a mismatch there is the usual reason it fails. Credentials and the refresh token live in a password manager, never in a shared folder or a repository.
  2. Before building anything else, I pulled one closed, already reconciled month and compared it line by line with the manual export: account numbers, dates, amounts, sign convention. Nothing else got written until it matched exactly.
  3. The script refreshes the token before every call, handles pagination over the full date range, writes dated files and logs every run (time, range, row count, errors). A silent failure is worse than a loud one. Without the log, a failed night just leaves the dashboard stale.
  4. In Power BI, only the query step that reads the file changed. The model stayed the same, and the totals were checked against the P&L again. The plan kept the manual export running in parallel for a full quarter before retiring it.
  5. The script runs nightly and the Power BI refresh follows with a buffer. There is a reminder around day 90, because the refresh token expires after 100 days without use and then someone has to redo the consent screen by hand.
  6. The developer account and the credentials have a named owner, and a short runbook says what the script does, where it lives and who to call when a refresh fails.

What it doesn't solve

The API automates the general ledger only. Revenue by sponsor, study and clinic still comes from the billing team's spreadsheets, because QuickBooks doesn't hold that breakdown. Closing that gap depends on the data entry fixes in the QuickBooks audit, not on more code.
